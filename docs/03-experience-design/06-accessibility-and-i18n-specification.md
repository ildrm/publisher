## Product and content requirements

Target WCAG 2.2 AA for applicable web interfaces; this is a proposed target, not a conformance claim. Apply semantic structure, accessible names, logical focus order, keyboard alternatives for drag/drop, visible focus, text alternatives, error identification, reflow and reduced-motion support. Screen-reader announcements distinguish save, failure and completion. Review use of color with actual rendered contrast; never rely on automated checks alone. Provide non-drag move controls for chapters and plot cards. Respect browser zoom, contrast preferences and user font settings. The source [W3C WCAG 2.2 specification](https://www.w3.org/TR/WCAG22/) is a standards reference; implementation and current applicable legal obligations require independent review.

Use Unicode and language tags on UI and manuscript nodes; support bidirectional isolation where interpolating names or mixed scripts. UI locale, UI direction, manuscript language and document base direction are separate settings. Preserve Unicode normalization and combining marks without altering author intent. Test Arabic/Persian mixed with Latin numbers and punctuation, Hebrew, CJK and IME composition, emoji, and assistive technology navigation after save, restore and export. Use logical CSS properties and allow text expansion, locale-sensitive number/date formats and international names. Do not assume language determines territory or currency.

## Active interface language contract

The user's minimum 14-language request supersedes the original English-only assumption. The active local Author Studio offers `en`, `zh`, `hi`, `es`, `ar`, `fr`, `bn`, `pt`, `id`, `ur`, `ru`, `de`, `ja` and `pcm`, plus `fa`. This is the total-speaker interpretation recorded in [DEC-011](../00-governance/02-decisions-and-open-questions.md). Mandarin uses Simplified Chinese; Arabic uses standard written Arabic; regional Portuguese/Spanish variants, Traditional Chinese and separate Arabic dialect catalogs are not claimed. All non-English catalogs are implementer translation drafts without native human approval. No external translation service receives manuscript content.

The language selector is available before and after authentication, uses native language names with an English identification aid, and has a localized accessible name. Set the document root `lang` and `dir`; Arabic, Persian and Urdu use RTL. Keep protocol headers, commands, file formats, language tags and the Publisher brand literal. Isolate author names, project/chapter titles, filenames and interpolated mixed-script identifiers. Translate application-owned labels, hints, dialogs, accessibility names, form errors, statuses, import warnings and recovery messages; keep machine error codes stable. Preserve descriptors so an already displayed application message can render again after switching languages. Browser-owned dialog chrome, operating-system text and downloaded author content are outside the catalog contract.

For a fresh page, use a supported `lang` link parameter, then saved device preference, then the first supported browser language, then English. After authentication, a saved non-null account preference takes precedence. Existing accounts migrate with a null preference so their browser/device choice remains usable until they select one. Save interface selection immediately on the device and synchronize it through the authenticated, CSRF-protected account preference endpoint; report a synchronization failure without discarding the usable local selection. Restricted device storage must not prevent in-memory switching or authoring. Account synchronization must preserve the latest explicit choice when requests overlap.

Changing interface language must not recreate the editor, translate or rewrite manuscript text, change manuscript metadata, reset undo history, create a revision, or clear unsaved/conflict/recovery state. Editor and read-only revision preview retain the manuscript's own `lang`/`dir`. Manuscript language remains an independent language-tag field rather than a 15-option restriction. Date/number/plural formatting uses the selected interface's formatting locale. Nigerian Pidgin uses `en-NG` for browser Intl number/date/plural rules and its own Pidgin message catalog; this is not a claim of native `pcm` Intl support. Currency selection remains independent and no commerce currency UI is implemented in this slice.

For EPUB and digital PDF, preserve headings, reading order, language and accessible alternatives; validators supplement manual reading-system and screen-reader review. Print PDF/X and accessible digital PDF/UA have distinct goals and output profiles; neither compliance is asserted until validated against an agreed profile. Accessibility metadata is specific to the artifact and accurately describes limitations.

## Acceptance evidence

Accessibility lead chooses supported browser/screen-reader pairs and representative RTL/IME fixtures before pilot (OQ-007). QA records actual tasks, environment, observed failures, severity and remediation; independent review and any legal applicability assessment are separate gates. Include keyboard-only writing/export/purchase, screen-reader save-status announcements, focus return after dialogs and mixed-script round trips.

For the implemented authoring slice, require key/placeholder parity for all 15 catalogs; all-language selection and reload; migrated account and device/account precedence; translated API/auth/validation/conversion failures; Arabic/Persian/Urdu RTL; German/French expansion and CJK reflow; unsaved multilingual switching without editor remount; and exact Unicode source preservation through save/restore/export. The [dedicated multilingual browser run](../../implementation/evidence/i18n-e2e-results.json) passed all 15 entry/unsaved/account switches, same editor DOM, Undo to empty/Redo to exact authored content, source/metadata preservation until retry, exact Unicode after save, French native validation and Japanese reload. Arabic desktop/Urdu mobile axe scans reported zero violations; 1440×960/390×844 exercised states had no document-width overflow. Current strict build, 47 Python/9 JS application tests, separate reference tests and authoring regression also passed in [implementation evidence](../../implementation/test-evidence.md), with limits in [multilingual review](../../implementation/multilingual-review.md). Physical selection behavior, native language, actual IME, screen-reader and cross-browser/device review remain pending.
