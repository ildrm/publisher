## Proposed measurable requirements

Numerical values below are provisional engineering targets for pilot sizing and are not user promises. Establish representative workload, geography, devices, sample sizes and baselines before signing an SLA. Unless specified, measurements exclude scheduled maintenance only if the eventual customer contract explicitly allows it; pilot reports must show both raw and adjusted values.

## SLI and error budget use

For authoring availability, count valid authorized application requests to create, load and save manuscripts; exclude deliberate client validation rejections and abusive traffic only with published, reviewable classification. Track success/failure and latency separately: a slow successful response is still a latency miss. The monthly 99.9% objective allows 0.1% eligible failed requests, not a guarantee about any individual request. During low volume, report counts alongside ratios. A breached budget pauses discretionary risky changes until SRE and Product agree remediation. Save integrity, privacy and ledger balance are release-blocking invariants, not tradeable error budgets.
