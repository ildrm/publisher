# Implemented format boundaries

Version 0.2 · 2026-10-29 · Local implementation checkpoint; no production or human specialist approval. Owner: Engineering Lead; consulted/review perspectives: Product, Requirements, Architecture, Document Engineering, Security, Accessibility, QA, SRE, Editorial and Finance. Actual approval: pending where required. Current application and browser regression suites passed; this is not print, reading-system or Word-rendering certification.

Working private portable outputs: a full canonical project bundle, Markdown, plain text, HTML and deterministic DOCX ZIP package generated from a frozen manuscript snapshot. Source/schema/converter hashes, job states and artifact checksum are persisted. Tests inspect actual output, compare repeated DOCX bytes, validate required XML/package parts, confirm escaped HTML, enforce authorization and retain previous good artifacts on failures.

The current converter is `publisher-portable-2`. DOCX carries each manuscript chapter's own language and paragraph/run bidi metadata rather than borrowing the interface locale. Automatic paragraph direction follows strong text direction with a language fallback for neutral content. Tests exercise Arabic, Persian, Urdu, Hindi, Bengali and Chinese alongside mixed English text, and compare repeated output bytes. DOCX import preserves tab characters, line/carriage breaks and supported hyphens, and respects explicitly disabled bold/italic/strike flags. Export writes breaks/tabs, ordered-list start values and supported numeric/Roman/letter formats; continuation paragraphs avoid duplicate list numbering. Required package XML is parsed before success, so XML-invalid source fails DOCX conversion without altering canonical text or earlier artifacts. These tests establish bounded XML/package semantics and reproducibility, not Microsoft Word layout/rendering fidelity.

Imports: UTF-8 text, Markdown headings with remaining syntax preserved literally, and a constrained DOCX parser for paragraph/heading/emphasis. Archive/size/ratio/DTD/entity/active-content checks run in a bounded child process. Unsupported tables, images, notes, hyperlinks, list numbering and layout raise review warnings; confirmation must acknowledge every warning; original bytes remain privately downloadable. No full malware scan or kernel sandbox is claimed. Rich clipboard constructs unsupported by the active schema are blocked with a visible message.

DOCX export still omits hyperlink targets and quote styles; nested numbering/layout needs review in Word, as disclosed before export. The ordered-list repairs do not establish every nested layout or regional typography. This is a tracked fidelity delta, not full FR-FMT-001 completion. EPUB, digital accessible PDF, printer-ready PDF and physical proofs are **not implemented/validated**. No external format-validator, Word-renderer or physical-printer sign-off has occurred. G3 remains partial and BLK-005 must be resolved before production. See [current evidence](test-evidence.md).
