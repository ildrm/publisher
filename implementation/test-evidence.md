October 29, 2026. Owner: Engineering/QA. Evidence is bounded to the local Author Studio, not production or full-platform acceptance.

**Current aggregate and both browser runs: PASS.** [Verification index](evidence/verification.json) records exit 0 for strict build, application/localization tests, documentation checks and separate reference tests. [Multilingual browser results](evidence/i18n-e2e-results.json) record all 15 entry-interface choices and all 15 unsaved-draft/account-preference switches in installed Chrome through Playwright. The same editor DOM survived every switch; Undo returned to empty content and Redo restored the exact authored draft. The pending draft and its manuscript language/direction survived switching; the server revision/source stayed unchanged while save requests were blocked, and the exact authored Unicode persisted after explicit retry. Japanese interface choice survived reload, and a French native form-validation message matched its catalog. Checks included 1440×960 and 390×844 viewports with no document-width overflow in exercised states. [Arabic desktop and Urdu mobile axe checks](evidence/i18n-axe-results.json) reported zero violations in those states. This is automated local evidence, not native language, physical IME/device, screen-reader or WCAG certification.

All 15 catalogs have the same 330 keys, nonempty strings and preserved placeholders. Current automated tests cover Intl/plural behavior, account/device/browser preferences, schema-1 upgrade through migration 002, localized API/conversion descriptors and authoring regression. Browser fault injection also confirmed that restricted storage plus a failed account synchronization leaves the chosen interface and manuscript usable without falsely claiming persistence. Physical text selection behavior, real IME composition, screen-reader/device coverage and language quality remain manual acceptance work. See [multilingual review](multilingual-review.md).

Defects observed and repaired rather than skipped: password accessible-name pollution; asynchronous import reading a cleared form target; irrelevant registration token rejected by strict input validation; editor initialization generating a false recovery copy; preview remount risking unsaved text; versioned request retry/revocation order; local process interruption of export work. Final browser assertions include the fixed paths.

The multilingual increment additionally replaces the incomplete English interface with local catalogs and language preferences, separates interface direction from manuscript metadata, and carries system message descriptors for re-rendering after language switches. Device persistence is claimed only after storage read-back confirms the current choice; stale preference-write failures are ignored. Paste handling remains installed after locale updates; recovery-copy adoption initializes the save controller before queuing recovered content; busy recovery/download actions retain error handling; mobile chapter controls remain usable. Translation draft completeness is not native linguistic approval.

The backend review repaired DOCX language/bidi metadata, breaks/tabs, ordered-list starts/styles/continuation and disabled formatting marks; invalid XML cannot become a successful DOCX artifact. Converter version is `publisher-portable-2`. Tests establish XML/package semantics and deterministic bytes, not Microsoft Word rendering. Scrypt no longer holds SQLite's writer lock during expensive computation, and credential/reset state is rechecked before session creation. Session-key publication is atomic. Conversion output/state checks are bounded; interrupted jobs cannot promote artifacts. Failed partial backups are removed and restored database/WAL files regain private permissions. Malformed Unicode, non-ASCII CSRF tokens and invalid revision selectors fail safely; imported hidden filenames retain nonempty chapter titles and invalid local origins are rejected. See [security review](security-review.md) and [format boundaries](format-validation.md).

Not executed/claimed: hosted CI, staging/cloud deployment, real providers or email deliverability, production TLS/encryption/replication, independent security/a11y/legal/finance approval, regional DR/SLO/load/cost proof, actual IME/screen-reader devices, EPUBCheck/PDF/physical print proof, public publication, commerce/ledger/payout or 3D. These gates remain explicit in release-readiness.md.
