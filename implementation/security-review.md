# Local security review

Version 0.2 · 2026-10-29 · Local implementation checkpoint; no production or human specialist approval. Owner: Engineering Lead; consulted/review perspectives: Product, Requirements, Architecture, Document Engineering, Security, Accessibility, QA, SRE, Editorial and Finance. Actual approval: pending where required. Current strict build, 47 Python application/localization tests, 9 JS autosave/i18n tests and both browser suites passed; this is bounded engineering evidence, not an independent security audit.

Implemented controls: scrypt hashes with random salts; opaque random sessions stored as hashes; HTTP-only SameSite cookies; server-derived CSRF; same-origin mutation/content-type checks; auth throttling and request budgets; single-use expiring verification/recovery tokens; recovery invalidates sessions; current per-project grants and access epochs; CAS and scoped receipts; immutable revision/artifact/audit triggers; private file permissions; escaped HTML export and validated semantic AST; redacted method/status/correlation logs; child conversion has minimal environment and CPU/time/file budgets; fresh artifact access checks; no public draft, AI, staff or money routes.

Negative tests cover unrelated accounts, viewer writes, owner-only sharing, revoked replay/download promotion, malicious href/AST/archive/XML, CSRF/origin, stale concurrency, unsupported formats and public/static traversal. Local audit hash chaining is tamper-evident only against limited accidental mutation; it is not independently anchored or proof against a privileged database operator. No pen test or ASVS certification occurred.

The current review added nine backend regressions and repaired these concrete defects:

- Expensive scrypt work now occurs outside SQLite's writer transaction; the current credential/reset state is rechecked before a session or reset result commits. A test permits an independent writer during password verification and rejects a credential invalidated during that work.
- Session-key creation publishes a complete private key atomically; concurrent initializers observe the same complete key and leave no temporary key files.
- Worker output size/shape and artifact promotion state are bounded. Malformed output and jobs marked interrupted cannot publish successful artifacts; prior good artifacts remain available subject to current authorization.
- Failed backups remove partial targets. Opening a restored database reapplies private permissions to the database and existing WAL/SHM files; local restore tests inspect those permissions. Encryption and regional recovery remain open.
- Malformed Unicode, non-ASCII CSRF tokens and invalid revision selectors fail through safe validation/denial paths without creating a revision. Hidden import filenames retain nonempty titles, and invalid local origins are rejected.
- Invalid XML cannot be promoted as a successful DOCX export; original canonical text is retained. DOCX XML semantics/deterministic bytes are tested, not Word rendering or security certification.

Language preference updates require the current authenticated user and valid CSRF. Shared catalogs localize explicit system messages and preserve stable machine codes/descriptors; they never recursively translate private manuscript payloads or send content to a translation service. Catalog/locale metadata are bundled locally. Device persistence messages require storage read-back, and a late preference failure for an older account/choice is ignored. The schema-1 migration preserves content and leaves legacy account preference null. [Multilingual review](multilingual-review.md) and [test evidence](test-evidence.md) record exact scope and results.
