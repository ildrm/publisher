# Accessibility and internationalization evidence

Version 0.2 · 2026-10-29 · Local implementation checkpoint; no production, native language or human accessibility specialist approval. Owner: Engineering Lead; consulted/review perspectives: Product, Requirements, Architecture, Document Engineering, Security, Accessibility, QA, SRE, Editorial and Finance. Actual approval: pending where required. Aggregate verification and both authoring/multilingual browser runs passed; exact results are in test-evidence.md.

The local UI uses semantic landmarks/headings, labeled forms, visible focus, actual modal dialog focus containment, keyboard chapter move controls, tab keyboard navigation, live save/error states, reduced-motion rules and independent manuscript language/direction. Editor is Tiptap/ProseMirror; Unicode is stored without normalization. Browser regression checks mixed Persian/Arabic/Japanese/combining accents/emoji through save and reload, 1440×960 and 390×844 layouts, keyboard focus, and an axe scan. See actual axe/e2e JSON and screenshots in evidence; zero automated violations is not a WCAG conformance claim.

Fixed during browser QA and included in the current authoring regression: password hint polluted accessible name; asynchronous form access broke import; editor setup emitted unnecessary changes; historical preview could have remounted the editor; header/tool/secondary text spacing and contrast were inspected. The multilingual review also preserved paste handlers during locale updates, corrected recovery-controller initialization, kept busy recovery/download actions guarded and repaired mobile chapter controls. These fixes do not establish independent accessibility conformance.

The current increment adds 15 catalog-backed interface choices covering the requested total-speaker top14 set plus Persian. Authentication and authenticated screens expose a labeled selector with native language names; root HTML `lang`/`dir`, localized accessible names, form validation, save/recovery/conflict states, import warnings and system errors update with the interface. Arabic/Persian/Urdu use RTL; mixed names/titles/filenames are isolated and logical CSS supports mirroring and expansion. Manuscript and revision preview retain their own language/direction, and switching the interface must preserve active editor content, undo/selection and unsaved state. Dates/numbers/plurals format through Intl; Nigerian Pidgin uses `en-NG` formatting and its own translated catalog. No author text is translated.

The [current Chrome browser run](evidence/i18n-e2e-results.json) passed all 15 entry-interface choices and unsaved-draft/account switching. It verified the same editor DOM after every switch and working Undo to empty content/Redo to exact authored content, unchanged server source/revision before retry, exact Unicode after save, independent manuscript metadata, French native form validation and Japanese reload persistence. Desktop (1440×960) and selected mobile (390×844) states had no document-width overflow. [Arabic desktop and Urdu mobile axe checks](evidence/i18n-axe-results.json) reported zero violations. These automated checks do not prove physical selection behavior, real IME composition, screen-reader completion or every state in every locale.

All translated catalogs are implementer drafts; no native speaker approval has been obtained. Real screen-reader/device/IME composition, regional language quality, long-document browser input/memory performance, high contrast and a complete WCAG 2.2 AA audit remain pending. Browser-native and operating-system dialog chrome follows the user's environment. See [multilingual review](multilingual-review.md) and [test evidence](test-evidence.md) for the bounded evidence and open work.
