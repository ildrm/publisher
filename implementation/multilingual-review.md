# Multilingual implementation and cross-role review

Version 0.2 · 2026-10-29. Scope: the local Author Studio and the supplied design/implementation documents. This is an engineering review using 22 role perspectives, not 22 human reviewers or actual specialist approval. [Aggregate verification](evidence/verification.json) and both authoring/multilingual browser runs are **PASS**: strict build, 47 Python application/localization tests, 9 JS autosave/i18n tests, documentation structural checks and separate 16 Python/3 JS reference tests. No full-platform or production acceptance is asserted.

## Requirement, interpretation and sources

The user explicitly required the website to support the “top 14 world languages” and requested review and fixes. The implementation interprets this as languages by total first- and additional-language speakers, rather than native speakers or website usage. This definition selects the following 14; Persian is retained as an additional fifteenth language. The selection is an implementation interpretation, not a claim the user selected these exact regional variants or approved translation quality. [DEC-011](../docs/00-governance/02-decisions-and-open-questions.md) supersedes the earlier English-only ASM-002 assumption; [NFR-I18N-001/002](../docs/02-requirements/06-nonfunctional-requirements-and-slos.md) now state measurable behavior.

Source review on 2026-10-29: the [AWS re:Invent 2024 DEV340 slides, page 8](https://reinvent.awsevents.com/content/dam/reinvent/2024/slides/dev/DEV340_Build-LLMs-for-low-resource-languages-with-SageMaker-HyperPod-clusters.pdf) contain a dated table attributed to Ethnologue and support the selected set. The [Visual Capitalist summary dated June 13, 2026](https://www.visualcapitalist.com/ranked-the-worlds-most-spoken-languages-in-2026/) lists the same set using total speakers; it is a secondary summary, not independent primary population research. The [ICLS language institute page](https://www.icls.edu/blog/most-spoken-languages-in-the-world) also describes a 2026 total-speaker list, but retains an older publication date. The [live Ethnologue ranking](https://www.ethnologue.com/insights/ethnologue200/) returned HTTP 403. Its current full primary data was not verified. This project makes no precise speaker-count, market-coverage or permanent ranking claim and does not reproduce a licensed population dataset.

## Implemented locale inventory

Current local inspection and automated tests confirmed all 15 catalogs have the same 330 entries, nonempty strings and preserved placeholders; exact parity must be maintained whenever new keys are added. Intl/plural, descriptor translation, negotiation and device read-back tests passed. All translated catalogs are implementer drafts, with no native human approval claimed. ## Behavior and boundaries

The selector appears on authentication and authenticated screens. Root HTML language/direction and application title update with the interface. Arabic, Persian and Urdu mirror interface layout, with logical spacing, directional keyboard tab movement and mixed-script isolation. The dedicated browser run passed all entry interfaces and exercised desktop/mobile reflow without document-width overflow; actual devices and broader state coverage remain manual work. Locale choices use native names and an English aid so users can recover from selecting an unfamiliar language.

A fresh page chooses supported `?lang=`, then stored device choice (`publisher.ui.locale`), then supported browser language, then English. A saved non-null account preference wins after authentication. Migration `002_interface_locales.sql` adds a nullable account locale; legacy accounts retain their initial browser/device choice until selection. Explicit authenticated choices synchronize through `PUT /api/preferences` with current session and CSRF checks. An account synchronization failure leaves the selection usable and displays a translated failure. Device persistence is claimed only after reading back the selected value; blocked storage still permits in-memory switching. Preference writes are queued, and a late failure for an older choice/account cannot replace the current message or imply that the current choice failed.

The manuscript's language and base direction remain independent fields. Switching interface language must preserve editor instance/content/selection/undo state, pending save or recovery state, revision history and export source. User names, titles, manuscript content, import text, filenames and canonical source are never passed through message translation. Newly generated default chapter labels can use an interface catalog at creation, then become ordinary stored titles and remain unchanged on later switching. Import/export keeps the existing fidelity disclosures. This feature translates the application interface and application-owned system messages, not books, design documentation, legal agreements or operating-system/browser chrome. No external translation API or model provider is invoked.

Requests send `Accept-Language`; localized responses identify `Content-Language`. Authentication, validation, save/recovery/conflict, conversion warning and generic failure messages use shared catalogs and stable `messageKey`/`messageParams` descriptors. Descriptors are retained for rendering after another language switch; machine error codes remain stable. Only explicit system-message fields are localized, rather than recursively rewriting arbitrary payload strings. Interpolated identifiers/commands keep their literal values, and technical file-format/protocol names and Publisher stay literal. Unknown failures should use a translated safe generic message and keep unsaved source available.
