# Local runtime and deployment boundary

The executable local environment needs Python 3.14, Node 26 and npm. It has no mandatory external service or commercial account. `npm ci`, `npm run build`, and `python3 apps/api/main.py serve` build and start the application. SQLite, hashed account/session records, private local mail and export blobs are under `.data/`, ignored by Git. The server binds loopback and rejects staging/production configuration. Do not expose this development server to the internet.

One server process owns each data directory via a file lock. SQLite uses WAL, foreign keys, and synchronous FULL transactions; immutable history/artifact/audit triggers and unique command receipts are real migration constraints. A restarted local server fails interrupted export jobs visibly and resumes queued jobs. A failed/interrupted export can be requested again with a new command key; existing artifacts remain unchanged. Worker child processes receive a minimal environment, CPU/time/file budgets and no service credentials. This is not a verified kernel network sandbox or malware scanner.

Back up to a new private file with `python3 apps/api/main.py backup --destination /private/tmp/publisher-backup.sqlite3`. Preserve the private `session.key` separately if retaining sessions is required. For an isolated restore, stop any process using the target directory, copy the backup as `publisher.sqlite3` in a new mode-0700 data directory, and run `python3 apps/api/main.py check --data-dir <directory>`. Test sign-in, revision hashes, project grants and artifacts before enabling writes. Never replace a live database or copy only its main file while WAL writes are active. Backup to a different name rather than overwrite previous evidence.

Production needs an approved database/replication failure model, encrypted storage and backups, TLS/proxy/session configuration, production WSGI/runtime and queue isolation, approved mail provider, residency/retention policy, restore exercise, monitoring and independent assurance. No cloud account, region or infrastructure target was approved, so this repository does not pretend to provision one. CI is supplied as executable configuration; hosted execution has not been observed locally.
